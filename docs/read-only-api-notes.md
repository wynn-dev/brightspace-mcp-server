# Read-only workflow API contracts

The tools use the API versions discovered from the institution. Permissions, course configuration and API versions can make individual sources unavailable. Tools report that distinction instead of interpreting a denied read as an empty dataset.

| Area | D2L reference | Contract decisions |
|---|---|---|
| Assignments and feedback | [Dropbox](https://docs.valence.desire2learn.com/res/dropbox.html) | `submissions/mysubmissions/` returns `EntityDropbox` containers, each with `Entity`, `Submissions`, `Feedback` and `CompletionDate`. Flatten and sort all available submissions. Only feedback with `IsGraded: true` is exposed; no invented `feedback/myFeedback/` route. |
| Quiz attempts | [Quizzes](https://docs.valence.desire2learn.com/res/quiz.html) | Resolve the current user and pass `userId`, then filter returned attempts by `UserId` again. Completion is the nullable `Completed` timestamp. Respect `IsPublished`; a null score stays null. Read `SubmissionTimeLimit` and displayed nested rich text. Check only the authenticated user’s dedicated special-access route for dates/settings. A denied/missing response does not prove the default dates apply. An ongoing own-user attempt can establish its current deadline, not future attempts. |
| Content and completion | [Content](https://docs.valence.desire2learn.com/res/content.html) | Stable `content/myItems/` supplies scheduled items with `ItemId`, `DateCompleted`, `CompletionType` and `IsExempt`. It is not a complete progress inventory. Do not call unstable `content/userprogress/` using a stable version or equate read state with completion. |
| News and feed | [News/feed](https://docs.valence.desire2learn.com/res/news.html), [updates](https://docs.valence.desire2learn.com/res/updates.html) | Batch counts accept at most 100 course IDs. Counts of -1 are not zero. News uses numeric author IDs and separate created/modified timestamps. Support documented `MessageMetaData` and observed `Metadata`; derive the course from a same-origin `ApiViewUrl` when no explicit course ID is supplied. |
| Grades | [Grades](https://docs.valence.desire2learn.com/res/grade.html) | Join own visible values to grade objects, categories and setup. Fetch own bulk exemptions where permitted; do not expose values from that management-oriented response. Keep private comments out and official final separate. Refuse unsupported or incomplete calculations. |
| Calendar | [Calendar](https://docs.valence.desire2learn.com/res/calendar.html) | Event types and the occurrences route require LE 1.94+. Normalize outbound timestamps to UTC with milliseconds; the connected institution rejects otherwise valid timestamps without milliseconds. Occurrences wrap `EventDataInfo` and `Occurrences`. A null occurrence timestamp stays null; it must not inherit a different occurrence's timestamp. Preserve all-day dates and exclusive end dates. |
| Groups and sections | [Groups](https://docs.valence.desire2learn.com/res/groups.html) | Resolve group membership using the authenticated user's ID in `Enrollments`. Own sections can return 404 when not configured. Do not expose other groups or infer membership when enrollment data is missing. |
| Course discovery/staff | [Courses](https://docs.valence.desire2learn.com/res/course.html), [users](https://docs.valence.desire2learn.com/res/user.html) | Course offering metadata supplies dates and semester, with permitted enrollment `Access.StartDate`/`EndDate` and explicitly typed semester/term ancestors as fallbacks. Accessible staff/contact document excerpts remain separate from verified roster entries. Active enrollment alone does not establish the current term. Role IDs are institution-specific; staff selection uses returned role labels with an explicit-label override. |
| Discussions | [Discussions](https://docs.valence.desire2learn.com/res/discuss.html) | Posts support `pageNumber`, `pageSize`, `threadId`, `threadsOnly` and `sort`. Local unread/own/since filters do not imply exhaustion of the API page chain. Bounded multi-page scans report continuation and retain matches from every scanned page. Do not call read-status mutations. |
| Checklists | [Checklists](https://docs.valence.desire2learn.com/res/checklist.html) | Support documented `Id` and live TU Delft `ChecklistId` on checklist records; preserve unidentifiable entries with an explicit limit; category records use `CategoryId`; items use `ChecklistItemId`. This API does not expose personal item completion. |

## Validation

`pnpm run build` checks the production TypeScript. `pnpm run test:run` runs synthetic API-contract tests, SDK-driven Streamable HTTP tests, and both compiled production entrypoints as subprocesses. The entrypoint suite builds current source, uses an isolated encrypted synthetic session, and replaces only remote fetch responses. It exercises every registered tool with populated fixtures and verifies GET-only Brightspace requests. Run it alone with `pnpm exec vitest run tests/e2e/entrypoints.test.ts`. Tests include real generated PDFs, Unicode continuation, streaming byte limits, paged submissions and errors, own-user privacy, grade-rule refusal, date/time-zone handling, source tracing and HTTP file-write exclusion.

Live checking uses the configured account and the production `AuthRunner` callback for automatic session renewal; manual `pnpm run auth` is needed only if automatic login fails or needs interaction. Limit live tests to GET requests and avoid printing tokens, personal scores or document bodies. A successful empty endpoint does not validate nonempty quiz, rubric, checklist or recurrence mappings; those require representative fixtures or a suitable course. No live account data belongs in test fixtures. See [the pre-merge review](pre-merge-validation.md) for the checks and live-access limitations.

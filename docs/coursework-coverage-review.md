# Coursework coverage review

Reviewed on 2026-09-15 against the configured TU Delft account, the compiled HTTP server and the D2L API contracts. All live Brightspace requests were GETs. No coursework was changed and no course documents were saved.

## Findings and implementation

| Reported limitation | Assessment and result |
|---|---|
| Checklist parsing | Confirmed defect. Live checklist rows use `ChecklistId`, although the [reference](https://docs.valence.desire2learn.com/res/checklist.html) describes `Id`. Accept both. Preserve entries with an unusable identifier and report incomplete detail access instead of silently dropping them. Child categories/items continue to use their distinct identifiers. |
| Outdated discovery | The public HTTP endpoint already advertises all 20 tools, including the nine additions. The reported missing tools were not reproduced at the server. Add `pnpm run diagnose` for stdio/HTTP version and inventory comparison, and include discovery metadata in `check_auth`. README separates restarting an old process from refreshing the client's cached discovery. Client-specific refresh remains dependent on knowing which client is affected. |
| Personal deadline extensions | Add reads of the authenticated user's dedicated [assignment](https://docs.valence.desire2learn.com/res/dropbox.html) and [quiz](https://docs.valence.desire2learn.com/res/quiz.html) special-access routes. Valid responses override dates, including explicit nulls; quiz timing/attempt overrides apply where supplied. Never enumerate other users. A 403 stops repeated probes for that activity kind within the call; 404 or malformed data does not prove that defaults apply. An ongoing own-user quiz attempt can establish its current attempt deadline. Work summaries label uncertain dates and avoid definitive overdue/closed claims. They warn when unverified dates exclude possibly extended work from the requested window. |
| Narrow deadline coverage | Keep the familiar calendar tool and add `includeReminders`, with explicit reminder/deadline kinds and guidance to `get_my_work` and `get_calendar`. Guidance is available to text-only and structured-response clients. This does not claim that calendar events constitute a complete work inventory. |
| Discussion filters per page | Add bounded `maxPagesToScan` (1–10), `pagesScanned` and `exhausted`. Continue past empty filtered pages, preserve matches when later reads fail, and return a continuation to the unread/failed page. A completed scan no longer retains the intermediate page's “more results” limit. |
| Search excludes document bodies | Add opt-in `documents` searches for PDF, HTML and text. Return physical PDF page references and source links. Bound files, characters, pages, bytes and discovery; skip explicitly hidden/locked nodes and known non-file topics. Report truncated/unsupported/unavailable content. File and match pagination are separate and documented. No persistent index or document writes. |
| Course details forbidden | Preserve the denied status. Use permitted [enrollment access dates](https://docs.valence.desire2learn.com/res/enroll.html) and, for a requested semester filter, an explicitly typed [semester/term ancestor](https://docs.valence.desire2learn.com/res/orgunit.html) where available. Report field provenance and retain unknown filter matches. Do not infer semesters from course codes or names. |
| Syllabus unavailable | Add a default-enabled content fallback to accessible course-guide candidates when overview text is missing/denied. Return bounded excerpts with source references separately from official overview data. `includeContentFallback: false` skips these reads. |
| Grade projections unavailable | Correct conservative behavior remains. No inferred grading rules, weights, hidden grades or exemptions. Existing verified Points/Weighted what-if calculations still run where all required rules are available. |
| Staff roster forbidden | Preserve the denied roster and return separate, default-enabled staff/contact document candidates. Excerpts are not converted into verified staff records or used to infer roles. |
| Checklist completion unavailable | Remains explicitly unknown. The checklist API does not expose personal completion. Scheduled content completion is a different source and is not guessed to represent checklist completion. No completion mutations or undocumented endpoint probes added. |
| Sections unavailable | Preserve the unavailable source and existing own-group memberships. A missing sections route is not evidence that group membership is a section, and cannot be fixed by changing a parser. |
| Reliability test gaps | Recheck existing token recovery coverage (expired sessions, concurrent JSON/file 401s, shared login, failed login/retry and repeated rejection) and ongoing quiz-state handling. Add regressions for verified/null/malformed/denied personal dates, active-attempt deadline scope, unverified date windows, checklist variants, sparse/failed discussion pagination, document bodies and fallbacks. Exercise discovery diagnostics and document search through production transports. |

## Validation

- Production TypeScript build and 262 tests across 33 files, including every tool through compiled stdio and HTTP entrypoints. The transport suite checks read-only HTTP annotations, GET-only Brightspace requests, and rejection of `download_file` and syllabus `downloadPath` over HTTP. PDF, HTML and plain-text searches run through both transports.
- Live HTTP checks against the new build: 97 Brightspace GET requests. Three courses returned two requested checklists each, with 4, 3 and 3 child items respectively. Identifiers were retained correctly. The larger inventories paginate normally.
- Two live PDF body searches recovered text previously extracted by the reader, with physical page references. Their deliberately short excerpts correctly reported partial coverage.
- The unavailable overview recovered three readable course-material candidates (out of seven); the denied roster recovered one readable staff/contact candidate. Original endpoint failures and bounded fallback coverage remain visible.
- Enrollment metadata supplied date fields for all seven enrolled courses despite denied course-detail routes. This does not establish that every date or semester field is populated; typed semester-ancestor fallback is covered by fixtures.
- Live assignment special access was forbidden. The first failed probe and subsequent unverified dates were explicit. Successful extensions, removed restrictions and ongoing quiz attempt deadlines are validated with synthetic fixtures; they were not observed in the live account.
- Local stdio diagnostic: version 1.3.0, all 21 tools advertised, no mismatch. The compiled HTTP fixture diagnostic also reported all 20 tools without making any Brightspace tool requests.
- Public endpoint discovery: 20 advertised tools, none missing. It was still running version 1.2.8 during this branch's validation; the diagnostic correctly reported a mismatch with local version 1.3.0. The production process was not restarted for branch testing.

No new live browser-login exercise was necessary for these changes: auth code is unchanged and its regression suite is retained. The preceding [pre-merge review](pre-merge-validation.md) records the successful isolated live automatic-login check. No personal scores, document bodies or credentials were committed as fixtures.
